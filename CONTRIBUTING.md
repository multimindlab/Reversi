# Contributing

```sh
npm install
npm test          # builds, runs the TypeScript tests (core, CLI, server)
npm run test:py   # Python SDK tests, including a live run against the built server
npm run example   # end-to-end demo
```

Both test commands must pass. CI runs them on Node 22 and Python 3.9 and 3.12.

## Ground rules

- **Say what is true.** If a feature is planned, the README and docs say planned. Do not add code
  that looks like enforcement but returns success as a placeholder.
- **Fail closed.** When journaling or a check errors, the call is blocked, not allowed.
- **Rollback and approval are operator actions.** Nothing an agent can call may approve its own
  call or trigger rollback.
- **Every behaviour change needs a test**, especially anything touching the ledger hash, rollback,
  scope sealing or the server's auth.
- **Cross-language parity.** The Python SDK must agree with the TypeScript code. Fixtures live in
  `conformance/` and are generated by `node scripts/gen-fixtures.mjs` (CI runs it with `--check`).
  Changing the ledger hash input, the canonical JSON rules or manifest validation is a
  format change: update the schemas in `schemas/`, regenerate the fixtures, and say so in the PR.
