Start the server (see [deployment](/operations/deployment) for every option):

```bash
REVERSI_MANIFESTS=./tools.yaml REVERSI_KEYS=./keys.json node packages/server/dist/main.js
```

All `/v1` routes need `Authorization: Bearer <API key or OIDC token>`. `GET /healthz` and `GET /readyz` are open;
`GET /metrics` needs an auditor credential unless `REVERSI_METRICS_PUBLIC=1`. [Roles](/operations/authentication) gate each route.
Request and response bodies are JSON, except where noted. Bodies are capped at 1 MB.

Examples in these pages use `$KEY`, `$AGENT_KEY`, `$OPS_KEY` and so on for credentials, and `http://127.0.0.1:7421` for the
server. They were run against a local server.

| Plane | Role needed | Routes |
|---|---|---|
| Agent | `agent` | [runs](/api-reference/runs): open a run, `intents`, `outcome` |
| Read | `auditor`+ | run state, plan, export, reports, search, impact, alerts, status, approvals, ledger verify, bundles |
| Approve | `approver`+ | approve, deny, pre-approve, delegations |
| Operate | `operator`+ | compensation, resolve, rollback, simulate, replay, registry read ([operator](/api-reference/operator)) |
| Admin | `admin` | halt, resume, break-glass, publish or approve manifests and policy, keys, holds, retention, anchor, reload ([admin](/api-reference/admin)) |

Roles are cumulative: each includes the ones before it. Agents see only the runs they opened.

| Status | Meaning |
|---|---|
| 400 | Invalid body, id or query |
| 401 | Missing or invalid credential |
| 403 | Role or permission cap forbids it |
| 404 | Unknown run (also for another agent's run), approval, or a feature that is not enabled on this server |
| 409 | State conflict (duplicate run id, outcome already reported, approval already decided, a saved configuration that did not load) |
| 413 | Body over 1 MB |
| 502 | Anchor delivery failed |
| 503 | Ledger unavailable; the request was refused (fail closed) |

Errors are `{"error": "message"}`. Policy refusals are **not** errors: `POST …/intents` returns 200 with `"decision": "block"` and `reasons`.

**Features that are not enabled** answer 404 with a message saying why, for example `no retention settings`, `capture is off`,
`no manifest registry folder is configured on this server`, `signed bundles are not enabled on this server`.
On the standalone `reversi-server`, `/v1/connectors` returns an empty list (the gateway console fills it in), and
`/integrations/slack/actions` answers 404 unless `REVERSI_SLACK_SIGNING_SECRET` and `REVERSI_SLACK_USERS` are set.
