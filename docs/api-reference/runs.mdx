Agents see only runs they opened (another agent's run is a 404). Auditors and above can read any run.

## `POST /v1/runs`

```json
{ "permissions": ["orders:write"], "run_id": "optional", "mode": "enforce", "reason": "why this run exists" }
```
→ `201 {"run_id","mode","scope_seal"}`. Permissions must fit within the key's `max_permissions`.

## `POST /v1/runs/{id}/intents`

Authorize a call and journal its intent. Execute the tool only on `allow` or `would_block`.

```json
{ "tool": "create_order", "args": {"sku": "BOOK-1"}, "reason": "customer asked", "depends_on": [0] }
```
→ `{"decision":"allow","step":3}` · `{"decision":"would_block","step":3,"reasons":[…]}` · `{"decision":"block","reasons":[…]}`

A call waiting for approval is a `block` whose reason names the request:
`approval required: request apr_… is pending an operator decision; retry after it is approved`. After an approver decides it,
send the same intent again ([approvals](/concepts/approvals)). Violations also come from [policy](/concepts/policy),
[content checks](/concepts/content-checks) and the kill switch.

## `POST /v1/runs/{id}/steps/{n}/outcome`

```json
{ "status": "succeeded", "result": {"order_id": "ord_1"} }
{ "status": "failed", "error": "…" }
{ "status": "uncertain", "error": "timeout" }
```
`result` is used only to build the compensation arguments named in the manifest. It is hashed, not stored in the ledger.

## `GET /v1/runs`, `GET /v1/runs/{id}`

Run state, including `unresolved` step numbers.
