---
title: The ledger
description: An append-only, hash-chained record of every decision.
---

One JSON object per line. Each record's `hash` is SHA-256 over the canonical JSON (sorted keys, no whitespace) of
the record without `hash`; `prev_hash` is the previous record's `hash` (64 zeros for the first).

```json
{"seq":2,"ts_ms":1700000000003,"run_id":"golden-1","step":0,"actor":"agent","tool":"create_order",
 "payload_hash":"a3c9…","reason":"customer asked","event":"succeeded","detail":"","prev_hash":"…","hash":"…"}
```

Events: `run_started`, `intended`, `approved`, `blocked`, `would_block`, `succeeded`, `failed`, `uncertain`,
`compensating`, `compensated`, `compensation_failed`, `unrecoverable`, `deferred`. Every record has a non-empty `reason`.

## What it stores

Only **hashes** of arguments and results. Secrets and personal data in tool arguments never reach the ledger.

## Verifying

<CodeGroup>
```bash CLI
reversi verify ledger.jsonl
```
```bash Python (no install of Reversi needed)
python -m reversi_sdk verify ledger.jsonl
```
```text Browser
Open viewer/index.html and choose the file.
```
</CodeGroup>

All three implementations are tested against the same fixtures (`conformance/`), generated by the TypeScript code.

## What it proves, and what it does not

- Detects: edited records, deleted records in the middle, reordering.
- Does **not** detect: someone with write access rewriting the **whole** file consistently, or cutting off the end.
- Fix: periodically publish the head hash somewhere the writer cannot change (another system, a signed timestamp).
  This is tamper-**evidence**, not tamper-prevention.
